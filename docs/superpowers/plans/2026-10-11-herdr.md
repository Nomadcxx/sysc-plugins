# herdr Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `org.sysc.herdr`, a sysc-shell plugin that monitors herdr terminal sessions and coding agents from a bar badge and an attached 440×560 panel, with event-driven updates, blocked/done notifications, agent output peek, and new-session creation.

**Architecture:** One Go library package (`plugins/herdr`) holds all logic: a newline-delimited-JSON herdr socket client (one-shot dials for calls; a single `events.subscribe` connection per session for push updates), session discovery via `herdr session list --json`, a pure view model, pure renderers over `plugin/v1` nodes, a service that owns polling/events/notifications, and an actions layer for terminal/CLI/socket side effects. `cmd/sysc-plugin-herdr/main.go` is only wiring: protocol event loop, settings, and input dispatch.

**Tech Stack:** Go 1.26.4; `github.com/Nomadcxx/sysc-shell/plugin/v1` + `plugin/lint` (pinned v0.0.0-20261005234519-d16632ff376f); stdlib `net`/`encoding/json`/`os/exec`; repo internals `internal/identity`, `internal/barwidth`, `internal/capture`.

**Spec:** `docs/superpowers/specs/2026-10-11-herdr-design.md` (approved 2026-10-11). Read it; it is the source of truth for behavior. This plan turns it into tasks.

**Worktree:** run everything from `/home/nomadx/sysc-plugins/.worktrees/herdr` (branch `feat/herdr-plugin`). All paths below are relative to it.

Anything else fails validation.
- Tones only (`error`, `accent`, `subtle`, `` normal ``) — no arbitrary colors.
- Socket wire protocol (verified against herdr v0.9.1, protocol 22):
  - Request line `{"id":"...","method":"...","params":{...}}`, reply line `{"id":"...","result":{...}}` or `{"id":"...","error":{"code":...,"message":"..."}}`.
  - Call connections are one-shot: write one request, read one line, close.
  - A subscribed connection accepts exactly **one** `events.subscribe`; sending a second request **resets the connection**. All subscriptions (global types + one `pane.agent_status_changed` per known pane) go in that single request. Pane-set changes are handled by reconnecting with a fresh snapshot and a new single subscribe request.
- Behavior of pane status transitions must never notify on the first snapshot after (re)connect — only on observed `working → blocked` / `working → done` transitions afterwards.
- Fixtures and captures are fictional data only (public repo): invent names/paths (`/home/dev/demo`, session `demo`, agent `claude`).
- Cross-check every render tree with `shelllint.Tree` before committing renderer changes (tests do this automatically).

// socket.go
type APIError struct{ Code string; Message string }        // Error() => "herdr <code>: <message>"
type Event struct { Type string `json:"event"`; Data json.RawMessage `json:"data"` }
type SubSpec struct { Type string `json:"type"`; PaneID string `json:"pane_id,omitempty"` }
type Subscription struct { /* conn, bufio.Reader, events chan Event, done */ }
func CallOn(ctx context.Context, conn net.Conn, method string, params, result any) error
func Call(ctx context.Context, path, method string, params, result any) error // dials one-shot
func SubscribeTo(ctx context.Context, path string, subs []SubSpec) (*Subscription, error)
func (s *Subscription) Next() (Event, bool) // blocks; false when closed/errored
func (s *Subscription) Close() error
// SocketPath helpers live in discover.go (paths come from session list).
```

- `CallOn` writes `{"id":"c1",...}` + `\n`, reads one line, unmarshals `result` into `result`, maps `error` to `*APIError`. Result `{"type":"ok", ...}` shapes are decoded by callers into their own struct.
- `SubscribeTo` dials, writes ONE subscribe request, reads the ack line, then spawns a reader goroutine that pushes `Event`s until the conn errors/closes (then closes `events`). Any line without `event` field is ignored. Reader must never write to the conn afterwards.
- Bounded reads: `bufio.Scanner` with `scanner.Buffer(make([]byte, 64<<10), 4<<20)` (4 MiB line cap).

type Notification struct { Title, Body string; Summary bool }
type Options struct {

  SessionLog func(format string, args ...any)
  // Test seams (nil → real implementations):

  Subscribe func(ctx context.Context, sock string, subs []SubSpec) (*Subscription, error)

}
type Service struct { /* ... */ }
func NewService(o Options) *Service
func (s *Service) Start(ctx context.Context)              // blocks until ctx done
func (s *Service) SetSettings(Settings)
func (s *Service) Refresh()                               // force rediscovery now
func (s *Service) SetActionError(msg string)              // cleared on any successful refresh
func (s *Service) Model() *Model                          // immutable snapshot for renderers
func (s *Service) Updates() <-chan struct{}               // coalesced wake-ups for the protocol loop
func (s *Service) Notifications() <-chan Notification     // debounced, buffered 16
func (s *Service) Close()
```

Internals:
- `Start`: immediate discovery, then `5s` ticker (`PollInterval`); discovery runs `List` in a goroutine with 6s timeout. Results feed `applyDiscovery` which updates `Model.Sessions` order/state and starts/stops per-session runtimes.
- Per-session runtime goroutine: loop { snapshot (socket `session.snapshot` call on `info.Socket`) → update doc; if first successful load: baseline statuses (no notifications) → subscribe request with `[{pane.created},{pane.closed},{pane.updated},{pane.focused},{workspace.created},{workspace.updated},{workspace.renamed},{workspace.closed},{workspace.focused},{tab.created},{tab.updated},{tab.closed},{tab.focused}] + per-pane {pane.agent_status_changed, pane_id}` → select {ctx.Done, s.refresh (force resubscribe+snapshot), sub.Next, 30s refresh ticker} }. On pane.created/closed event: drain and `continue` outer loop (reconnect + fresh snapshot + new subscribe). On agent_status_changed: apply status, record `since[paneID]=now` on change, queue transition notification if `old==working && new in {blocked,done}` (respecting settings) unless `!baseline`. On sub error/closed: mark stale, backoff `1s→2s→…→30s`, reconnect; after reconnect take a fresh snapshot, update statuses **without notifying** (re-baseline), resubscribe.
- Notifications: queued notifications are held in a slice; a `500ms` (`NotifyDebounce`) timer flushes: 1 → emit as-is (`Summary=false`); >1 → emit `{Title: "N agents need attention", Body: "<b> blocked · <d> done", Summary: true}`. Never emit when `Model.Stale` was true or during first baseline.
- `since` map: `paneID → time.Time` set on first observation of a status (baseline: now) and on each change; survives brief disconnects; cleaned when pane disappears.
- Session error fields: socket call failure → `SessionRow.Stale=true`, keep last doc, `Err` briefly set; herdr missing (`List` returns sentinel) → `Model.HerdrMissing=true`, keep last model.
- `Model()` builds fresh copies under mutex; `Updates()` closed channel is replaced by a 1-buffered wake channel pinged on any visible change (drop if full).
- Stopped sessions: on discovery, load `session.json` via `LoadStopped` (cached by dir mtime); store names in `SessionRow.StoppedWorkspaces`.
- `SetActionError("")` called by main on successful refresh.
