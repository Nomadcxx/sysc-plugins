# bitsub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build bitsub, a subscription tracker. It has an always-on Go service on archPC (SQLite store, reminders, Google Calendar and Gmail through `gog`, FX, MCP and a JSON API), a sysc-shell plugin that mirrors it on archPC and the laptop, and a skill that teaches MCP clients the conventions.

**Architecture:** `bitsubd` is the only process that touches the database. Every caller goes through one `service` layer, reached two ways: MCP tools at `/mcp` and the plugin's JSON at `/api/v1`. The plugin is a thin polling client. `subs` holds the pure domain code (money, dates, renewal maths, totals, snapshot types) shared by both sides.

**Tech Stack:** Go (repo `go.mod`, currently 1.26.10). `modernc.org/sqlite` is already a dependency. `github.com/modelcontextprotocol/go-sdk` is new: pin the latest v1.x release. `github.com/google/uuid` is already in go.sum. sysc-shell `plugin/v1` + `plugin/lint`. External binary `gog` ≥ v0.28.

**Spec:** `docs/superpowers/specs/2026-11-29-bitsub-design.md` (read it first; section numbers below refer to it). Companion plan for the protocol changes: `docs/superpowers/plans/2026-11-29-notify-actions-and-text-spans.md`. Task 14 depends on that plan.

## Global Constraints

- Work in worktree `~/worktrees/sysc-plugins-bitsub`, branch `feat/bitsub`. Never build or commit from `~/sysc-plugins` or `~/sysc-shell` (they hold other sessions' uncommitted work).
- Commit messages must not contain: agent, bot, claude, codex, llm, gpt-N, copilot, gemini, "generated by", co-author trailers or 🤖 (the `~/.git-hooks/commit-msg` hook rejects them). Write "MCP tools" and "skill".
- A fresh worktree has no beads DB, so commit with `BEADS_DB=<scratch copy of ~/sysc-plugins/.beads/beads.db with dirty_issues emptied>`. Check that `.beads/issues.jsonl` is unchanged after each commit.
- Go command caps: always `GOWORK=off go test -p 2 <pkgs>`. Never run uncapped `./...`, and run `-race` one package at a time.
- Money is integer minor units plus an ISO 4217 code. Never use floats for stored money.
- Calendar days are civil dates (`subs.Date`) in the system time zone (Australia/Melbourne). Instants are UTC.
- Display format: AUD first, original in brackets when it isn't AUD: `A$31.00 (US$20.00)`, `A$9.70 (€5.49)`, `A$17.00`. Symbols: AUD `A$`, USD `US$`, EUR `€`, GBP `£`, JPY `¥`, NZD `NZ$`, CAD `C$`. Any other currency uses its ISO code plus a space, e.g. `CHF 5.00`.
- The service binds `127.0.0.1:7733` plus the configured Tailscale address. LAN binding is opt-in only, and `0.0.0.0` is never the default.
- bitsub never cancels anything with a vendor. No tool, endpoint or skill text may suggest otherwise.
- Plugin views: a bar root is a row, a panel root is a column, every interactive node has ID, Name, Role and non-empty Events, and icon names come from the shell catalogue. Lint with `plugin/lint` at the declared sizes (see `docs/plugin-ui-rules.md`).
- The plugin must work on a host below protocol minor 29/30: no notification buttons, and single-tone header art.

## Review Focus

1. **Near-duplicate names from different MCP clients** ("Netflix", "netflix ", "NETFLIX"): `add_subscription` refuses with a duplicate error naming the existing entry unless `allow_duplicate` is set. Pinned in Task 4.
2. **Downtime across a reminder step and a renewal date** (archPC off for 10 days): on restart, only the current step for each subscription fires, every passed renewal gets exactly one `assumed` charge, and rerunning the rollover changes nothing. Pinned in Tasks 4 and 6.
3. **`gog` failing** (calendar scope missing, binary absent, timeout, malformed JSON): no event is deleted on a failed list, the error lands in channel status and the panel footer, the retry backs off, and the service keeps running. Pinned in Task 7.
4. **First run with no FX rates yet, or the fetch failing** while non-AUD prices exist: totals are marked approximate, items still show their original price, and nothing panics or shows `A$0.00`. Pinned in Tasks 2 and 5.
5. **Laptop plugin with the server unreachable or the token rejected (401)**: the offline card shows ("token rejected" for a 401), Keep/Cancel are inert, and on reconnect notifications already shown are not shown again, even after a plugin restart. Pinned in Tasks 11 and 12.

- Produces (`model.go`):

  - `type Subscription struct{ ID, Name, URL string; Price Money; Cycle Cycle; Interval int; Anchor Date; TrialEnd *Date; Intent Intent; Status Status; NoticeDays int; AccessUntil *Date; Category, PaymentLabel, Notes string; ReminderDays []int; CreatedBy string; CreatedAt, UpdatedAt time.Time; DeletedAt *time.Time }`

- Produces (`renewal.go`):
  - `NthRenewal(anchor Date, c Cycle, interval, k int) Date`: `k=0` is the anchor. Month and year cycles compute `anchor + k·interval` months and clamp the day to the month's length, never stepping from the previous result.
  - `NextOnOrAfter(anchor Date, c Cycle, interval int, day Date) Date`
  - `RenewalsBetween(anchor Date, c Cycle, interval int, after, through Date) []Date` (exclusive of `after`, inclusive of `through`)
  - `type TargetKind string` with `TargetTrialEnd, TargetRenewal`
  - `(Subscription) Target(today Date) (Date, TargetKind)`: trial end if `TrialEnd != nil && !TrialEnd.Before(today)`, otherwise `NextOnOrAfter(Anchor,…,today)`.
  - `(Subscription) CancelBy(today Date) Date`: the target minus `NoticeDays`.
  - `MonthlyMinor(amount int64, c Cycle, interval int) int64`: year÷12, week×52÷12, day×365÷12, month÷1, then ÷interval, rounding half away from zero.
- Produces (`totals.go`):
  - `type Totals struct{ MonthlyAUD, YearlyAUD, Next30AUD int64; Next30Count int; Approx bool }`
  - `ComputeTotals(subs []Subscription, rates Rates, today Date) Totals`. Monthly counts active subscriptions whose intent isn't `Cancel` (trials whose trial hasn't ended are excluded too). Yearly = Monthly×12. Next30 counts every target or renewal in `(today-1, today+30]` for active subscriptions, cancelling ones included. `Approx` = any non-AUD price missing a rate (that price is left out of the sums) or rates older than 7 days.
  - `type MonthTotal struct{ Month string /* "2026-11" */; AUDMinor int64 }`, `MonthlySeries(charges []Charge, today Date) []MonthTotal`: exactly 12 entries, oldest first, ending with the current month, zero-filled.
- Produces (`api.go`, the wire types for `/api/v1/snapshot`):
  - `type Item struct{ ID, Name string; Price Money; PriceAUD int64; PriceApprox bool; Cycle Cycle; Interval int; Target Date; TargetKind TargetKind; Intent Intent; CancelBy Date; ProbablyCharged bool }`
  - `type Action struct{ Key, Label string }`. Keys are exactly `keep:<id>`, `cancel:<id>` and `done:<id>`. Helper: `ParseActionKey(k string) (verb, id string, ok bool)`.
  - `type Notification struct{ Seq int64; SubscriptionID, Summary, Body, Urgency string /* low|normal|critical */; Actions []Action; IssuedAt time.Time }`
  - `type Channels struct{ CalendarSyncedAt *time.Time; CalendarError, EmailError, FXError string; NextDigest time.Time; FXDate Date; FXStale bool }`
  - `type Snapshot struct{ Items []Item; Totals Totals; Series []MonthTotal; Channels Channels; Notifications []Notification; LastSeq int64; ServedBy string; GeneratedAt time.Time }`
  - `PriceSuffix(c Cycle, interval int) string`: `/mo`, `/yr`, `/wk`, `/day`, and for interval > 1 e.g. `/3mo`.

**Interfaces:**
- Consumes: Task 3 store, Task 2 domain.
- Produces:
  - `type RatesSource interface{ Current() (subs.Rates, bool) }` (`false` until the first successful fetch).
  - `type ChannelSource interface{ Channels() subs.Channels }`
  - `New(st *store.Store, now func() time.Time, loc *time.Location, rates RatesSource, ch ChannelSource, servedBy string) *Service`
  - `type AddInput struct{ Name, URL, Amount, Currency string; Cycle subs.Cycle; Interval int; AnchorDate, TrialEnd string; Intent subs.Intent; NoticeDays int; Category, PaymentLabel, Notes string; ReminderDays []int; AllowDuplicate bool }`. String forms are used because they arrive from MCP and JSON. Defaults: Interval 1, Intent `undecided`. A request with only `TrialEnd` sets `AnchorDate=TrialEnd`. At least one of AnchorDate or TrialEnd is required.
  - `type UpdateInput` has the same fields as pointers (nil means unchanged), plus `ClearTrialEnd bool`.
  - `type Filter struct{ Status subs.Status /* "" = active */; Intent subs.Intent; Text string; IncludeDeleted bool }`
  - Methods (each mutating one writes an audit row with `actor` in the same Tx): `List(ctx, Filter) ([]subs.Item, error)`, `Get(ctx, idOrName string) (subs.Subscription, error)` (an exact id first, then a unique normalised-name match; ambiguity gives `*ValidationError`), `Add(ctx, actor string, in AddInput) (subs.Subscription, error)`, `Update(ctx, actor, id string, in UpdateInput) (subs.Subscription, error)`, `SetIntent(ctx, actor, id string, intent subs.Intent) (subs.Subscription, error)`, `ConfirmCancelled(ctx, actor, id string, accessUntil string) (subs.Subscription, error)`, `RecordCharge(ctx, actor, id, date, amount, currency string) (subs.Charge, error)` (amount empty means list price), `Upcoming(ctx, days int) ([]subs.Item, error)` (1–366, default 30), `Totals(ctx) (subs.Totals, error)`, `Delete(ctx, actor, id string) error`, `Restore(ctx, actor, id string) error`, `Snapshot(ctx, since int64) (subs.Snapshot, error)`, `Rollover(ctx) (int, error)`, `Changed() <-chan struct{}` (a buffered channel of size 1; every successful mutation does a non-blocking send, which bitsubd uses to trigger a calendar reconcile).
  - Errors: `ErrNotFound` (re-exported), `*DuplicateError{Existing subs.Subscription}`, `*ValidationError{Field, Reason string}`.
- Validation (spec §9), all in `validate.go`: name 1–80 chars after trim; currency via `subs.ParseCurrency` and present in the current rates (or AUD) when rates are known; amount `0 < x ≤ 100000.00`; interval 1–36; dates within ±10 years of today; intent and cycle enums; notice_days 0–90; reminder_days 1–5 distinct values in 1–60; url empty or `https?://`; payment_label ≤ 40 chars with no run of 8 or more digits once spaces and dashes are stripped; notes ≤ 2048 bytes; category ≤ 40.
- Rollover (`rollover.go`): for each active subscription, take every renewal date in `(last charge date or anchor−1, today−1]` (trial end counts as the first charge) and insert an `Assumed` charge at that date's rate. That's the current rate when no history is kept; `FXDate` records which rate was used. Unique-constraint conflicts are ignored, so the rollover is idempotent. Then clear `TrialEnd` once it's in the past. `ProbablyCharged` on an Item = intent `Cancel` and an `Assumed` charge on or after the last intent change. Store the intent-change date in `meta` key `intent_at:<id>`, or as a column if you prefer; your call.
- Snapshot: Items are active subscriptions sorted by `Target` ascending, then by name. Notifications are `NotificationsAfter(since, 50)`, filtered to subscriptions still active.
