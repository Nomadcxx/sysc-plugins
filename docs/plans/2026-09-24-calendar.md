# Calendar Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the month-only calendar stub with a read-only EDS calendar whose bar, event browser, keyboard navigation, and event actions meet the approved Noctalia/DMS parity target.

**Architecture:** The plugin reads expanded event occurrences from EDS on a worker and owns event conversion, navigation, filtering, and view state. The shell owns schedule-grid geometry, segmented-control rendering, focused-panel shortcuts, validated URL opening, and clipboard writes through additive protocol minor 8. No EDS content or credentials are persisted by the plugin.

**Tech Stack:** Go 1.26, existing `godbus`, a small RFC 5545 parser for EDS iCalendar objects, sysc-shell plugin protocol v1.8, and the shell's existing UI layout, render, focus, and geometry-lint code.

## Acceptance checklist

- The bar shows the upcoming event title and stable countdown, `Now` during an active timed event, and today's date when no timed event is upcoming.
- Month, Week, 4 Days, Day, and Agenda render usable navigation and event details.
- EDS owns account setup, recurrence expansion, sync, and cache. The plugin is read-only and distinguishes unavailable EDS, no sources, empty results, stale results, and read errors.
- Event links accept HTTP(S) only. Clipboard writes are bounded and optional; missing helpers produce visible errors. No calendar content is persisted.
- Schedule geometry handles all-day, multi-day, overlapping events, current time, clipping, focus, and keyboard navigation at declared dimensions.
- Visual captures are inspected and iterated; backend and geometry tests alone do not satisfy completion.
