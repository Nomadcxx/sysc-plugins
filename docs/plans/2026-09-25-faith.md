# Faith Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship `org.sysc.faith` 0.1.0 as the approved design describes. A cross on the bar gives a
public-domain prayer on left click. A right click opens a verse panel over bundled
Scripture and cross-references, with Adam Clarke's commentary as the one online extra.

**Architecture:** sysc-shell carries the `cross` and `menu_book` glyphs (Task S1, landed). In
this repository, a generator under `plugins/faith/internal/gen` turns pinned public-domain
sources into gzip data files. Pure packages under `plugins/faith` own the reference model, the
Scripture store, the pool, cross-references, the commentary client, prayers, wrapping, session
state, and views. `cmd/sysc-plugin-faith` owns the protocol loop, the commentary fetch, and the
timers. Every encoder write goes through one mutex.

**Tech Stack:** Go 1.26.4, sysc-shell `plugin/v1` and `plugin/lint` at a pin that carries
`cross`, and the standard library only.

## 2. Plan-level decisions

1. **One prayer per left click.** The host sends a primary click as `pointer`/`primary` on
   press and `activate` on release (`internal/shell/pluginhost.go`, `handlePluginBar`). The
   plugin prays on `activate`, opens the panel on `pointer`/`secondary`, and ignores
   `pointer`/`primary` and `pointer`/`middle`.
2. **One writer.** `v1.Encoder` has no lock but performs exactly one `Write` per message, so
   the client writes through a mutex-guarded `io.Writer`. That makes every `Snapshot` and `Call`
   atomic from any goroutine. Host calls (`notify`, `state.set`, `panel.open`) run on
   short-lived goroutines with a 3-second context, so the main loop never waits on a reply.
3. **Data format.** `data/<ID>.tsv.gz` holds one line per verse: `BOOK\tCHAPTER\tVERSE\tTEXT`,
   in canonical order, with USFM book codes. Poetry line breaks become spaces, and footnotes,
   cross-reference notes, headings, and Strong's attributes are dropped. `data/xrefs.tsv.gz`
   holds `BOOK\tCHAPTER\tVERSE\tREFS`, where `REFS` is up to five `;`-separated references
   (`PRO 8:22-30`) with positive votes, highest first. A range that crosses a chapter keeps its
   first verse only.
4. **The generator is committed, and so is its output.** `go run ./plugins/faith/internal/gen
   -bible-api <dir> -scrollmapper <dir>` rewrites `plugins/faith/data/` deterministically
   (sorted, gzip with a zero timestamp). `data/SOURCES.md` records the commits, licences, and
   SHA-256 of every output.
5. **Lazy load.** The store decompresses a translation on first use and keeps it until the
   translation changes. Cross-references load on the first panel open.
6. **Pool rules.** `data/pool.txt` holds exactly 365 references, one per line. There are no
   duplicates, and each range is at most four verses. Psalms are at most a quarter of the pool,
   and each Gospel appears at least ten times. There are no genealogies or census lists. Every
   reference must resolve in all three translations.
7. **Daily index.** `daily` picks `pool[daysSince(2000-01-01, local date) mod 365]`. A timer set
   for the next local midnight triggers the change.
8. **Refresh pauses while the panel is open.** The `refresh_minutes` timer skips while a panel
   view is open. It resets on a manual "new verse" and on any settings change.
9. **Commentary.** It is fetched only while the panel is open and `show_commentary` is on, from
   `https://bible.helloao.org/api/c/adam-clarke/{BOOK}/{chapter}.json`. `SYSC_FAITH_API_BASE`
   overrides the base for tests. The client uses a 10-second timeout and a 4 MiB
   `io.LimitReader`. Chapters are cached in memory (at most 16, least recently used). An entry
   shows at most 40 wrapped lines, and a longer one gets a subtle "Shortened" line. A failure
   shows one subtle line, "Commentary unavailable offline". A result for a reference the panel
   has left is dropped.
10. **Reader link.** "Read chapter" opens `https://biblehub.com/{bsb|web|kjv}/{slug}/{chapter}.htm`.
    The slug is the lower-case English name with spaces as underscores; Psalms is `psalms` and
    Song of Solomon is `songs`. The live check in Task 13 confirms the template. When
    `exec.LookPath("xdg-open")` fails at startup, the button is omitted.
11. **Protocol minor 4.** The views use subtle and accent tones, `Bold`, `Size`, `Disabled`,
    `PinEnd`, and `separator`.
12. **Catalog category `utilities`.** The closed category set has no better fit.
13. **Commit messages.** The owner's `commit-msg` hook rejects words including `agent`, `both`,
    `cursor`, `codex`, and `llm`. Screen every message.

## 7. Risks

- **Older shells.** A shell without `cross` refuses the bar, and the manifest cannot state a
  minimum shell version. Tag only after a shell release carries Task S1.
- **Binary size.** The three translations and cross-references add about 5 MB to the
  executable. That is acceptable for an offline Bible; a smaller cut is to drop a translation.
- **Mirror provenance.** The KJV and cross-references come through `scrollmapper`, not their
  originals. `SOURCES.md` pins the commit and records the upstream (OpenBible.info's CC BY file
  header is preserved in the mirror).
- **Commentary host.** The Free Use Bible API has no SLA. The plugin loses nothing else when it
  is down.
- **Text metric.** Wrapping at eight pixels per byte leaves short lines under the real face. It
  is the host's layout contract, and the lint tests hold the plugin to it.
