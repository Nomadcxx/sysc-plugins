# Faith Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship `org.sysc.faith` 0.1.0 as the approved design describes: a cross on the bar that
gives a public-domain prayer on left or right click, and a middle-click verse panel over the Free
Use Bible API with commentary and cross-references.

**Architecture:** One shell commit adds the `cross` glyph to sysc-shell's icon font. In this
repository, pure packages under `plugins/faith` own the reference model, verse pool, API client,
chapter cache, prayer corpus, text wrapping, session state, and view trees. `cmd/sysc-plugin-faith`
owns the protocol loop, the fetch workers, and the refresh timer. Every encoder write goes through
one mutex.

**Tech Stack:** Go 1.26.4, sysc-shell `plugin/v1` and `plugin/lint` at a pin that carries
`cross`, and the standard library only. The shell glyph uses Python fontTools.

## 2. Plan-level decisions

These fill gaps the design leaves open. They do not reopen its decisions.

1. **One prayer per left click.** The host delivers a primary click as `pointer`/`primary` on
   press and `activate` on release (`internal/shell/pluginhost.go`, `handlePluginBar`). The
   plugin prays on `activate` and on `pointer`/`secondary`, opens the panel on
   `pointer`/`middle`, and ignores `pointer`/`primary`.
2. **One writer.** `v1.Encoder` has no lock, so every `Snapshot`, `Patch`, and `Call` goes through
   a `sender` holding `sync.Mutex`, as in mini-docker. Host calls (`notify`, `state.set`,
   `panel.open`) run on short-lived goroutines with a 3-second context. This keeps the main
   loop from blocking while the receive goroutine waits on a full channel.
3. **Fetches never touch views.** A fetch runs on its own goroutine and returns a `fetchResult`
   on a channel to the main loop. The main loop applies it to the session and snapshots. A result
   whose request no longer matches the session's current reference and translation is dropped.
4. **Versification.** A bundled table of the 66 books uses the KJV versification: USFM ID,
   English name, and per-chapter verse counts. It drives `bible`-mode random selection and
   prev/next navigation. A fetched chapter's `numberOfVerses` wins over the table, and a
   reference beyond it clamps to the chapter's last verse.
5. **Pool rules.** `data/pool.txt` holds exactly 365 references, one per line, in the form
   `JHN 3:16` or `ROM 8:38-39`. There are no duplicates, and each range is at most four verses.
   Psalms are at most a quarter of the pool, and each Gospel appears at least ten times. No
   entries come from genealogies or census lists.
6. **Daily index.** `daily` picks `pool[daysSince(2000-01-01, local date) mod 365]`, so the verse
   changes at local midnight. A timer set for the next midnight triggers the change.
7. **Refresh pauses while the panel is open.** The `refresh_minutes` timer skips while a panel
   view is open, so the text does not change under the reader. It resets on a manual "new
   verse" and on any settings change.
8. **Offline behaviour.** The pool's BSB text is embedded (`data/pool-bsb.json`). If a fetch
   fails for a pool reference, the panel shows the bundled BSB text with a subtle "Offline:
   showing BSB" caption. In `bible` mode a failed fetch falls back to a pool pick. Commentary
   and cross-reference failures show a subtle one-line reason in their own section only.
9. **Cache bound.** The `chapters` state value holds at most 48 chapters and at most 192 KiB
   serialized, evicting least recently used first. The host limit is 256 KiB per value.
10. **Commentary bound.** A commentary entry shows at most 40 wrapped lines. If the entry is
    longer, a subtle "Shortened. Read the full note in the browser." line follows. The browser
    link is the chapter reader URL from Task 1.
11. **API base override.** `SYSC_FAITH_API_BASE` replaces `https://bible.helloao.org/api` and
    exists for tests. Responses are read through `io.LimitReader` at 2 MiB. The HTTP client
    timeout is 10 seconds.
12. **`xdg-open` is optional.** It is not listed in `requires.commands`. When `exec.LookPath`
    fails at startup, the panel omits the "Read chapter" button.
13. **Protocol minor 4.** The views use subtle and accent tones (minor 1), `Bold`, `Size`,
    `Disabled`, and `PinEnd` (minor 2), and `separator` (minor 4).
14. **Catalog category `utilities`.** The closed category set in `plugin/catalog.Categories`
    has no better fit. Adding one is shell work outside this plan.
15. **Commit messages.** The owner's `commit-msg` hook rejects words including `agent`, `both`,
    `cursor`, `codex`, and `llm`. Screen every message.

## 7. Risks

- **Older shells.** A shell without the `cross` glyph refuses the bar, because an unknown icon
  fails conversion and the user sees a failure card. The manifest cannot state a minimum shell
  version, so `faith-v0.1.0` is tagged only after a shell release includes S1. A minimum-shell
  manifest field is a separate shell issue.
- **API availability.** The service is free, has no SLA, and has one host. The embedded pool
  text keeps the bar, tooltip, and prayers working offline. Only other translations, commentary,
  and cross-references degrade.
- **Versification drift.** Translations differ at chapter ends, for example 3 John 1:14–15.
  Clamping to the fetched chapter's `numberOfVerses` covers this. Task 3's table test pins the
  KJV totals.
- **Text metric.** Wrapping at eight pixels per byte leaves short lines under the real face. It
  is the host's layout contract, and the lint tests hold the plugin to it.
